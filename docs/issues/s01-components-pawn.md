# Hand-maintained roster restates a declared set — components/pawn

> **Related:** [issues/README](README.md) · [tools/audit](../../tools/audit/README.md) · [rule source](../../docs/issues/core-stat-single-source.md)

## What breaks

Rule `S01` — hand-maintained roster restates a declared set — holds in 15 places under `components/pawn`. Each one is listed below with the evidence the audit required before it would record a fail.

The clearest case: SLOTS hand-lists all 17 members of the `EquipmentSlot` union, so a slot added to the union renders nowhere in the equipment doll and its item cannot be unequipped from the UI.

## Evidence

- [`src/lib/components/pawn/EquipmentDoll.svelte:25`](../../src/lib/components/pawn/EquipmentDoll.svelte#L25) — SLOTS hand-lists all 17 members of the `EquipmentSlot` union, so a slot added to the union renders nowhere in the equipment doll and its item cannot be unequipped from the UI.
  - src/lib/components/pawn/EquipmentDoll.svelte:25-43 — `const SLOTS: { slot: EquipmentSlot; label: string }[]` written out by hand, one literal per slot ('head', 'mainHand', 'bodyOuter', 'offHand', 'bodyMid', 'bodyBase', 'bracers', 'greaves', 'gloves', 'belt', 'boots', 'socks', 'back', 'back2', 'amulet', 'ring', 'ring2'), and the template at src/lib/components/pawn/EquipmentDoll.svelte:100+ renders only what this array contains.
  - The set is declared at src/lib/game/core/types/items.ts:73-90 — `export type EquipmentSlot = 'mainHand' | 'offHand' | 'head' | 'bodyBase' | 'bodyMid' | 'bodyOuter' | 'gloves' | 'boots' | 'socks' | 'bracers' | 'greaves' | 'ring' | 'ring2' | 'amulet' | 'belt' | 'back' | 'back2'`. Today the two agree at 17 members each; the array is a full restatement, not a subset, and it is not derived from the union (an array literal of union members type-checks whether or not it is complete — TypeScript raises no error for a missing member).
  - Concretely: add e.g. `| 'shoulders'` to src/lib/game/core/types/items.ts:90 and give an item `armorProperties.equipmentSlot: 'shoulders'`. Equip resolves fine — src/lib/game/core/rules/gear/equipment.ts:74 `getEquipmentSlot` reads the slot straight off the item and src/lib/game/core/rules/gear/equipment.ts:116 `equipItem` writes `pawn.equipment.shoulders` — but EquipmentDoll never iterates that key, so the doll shows no cell for it, `inst('shoulders')` (src/lib/components/pawn/EquipmentDoll.svelte:45) is never called, and the `onUnequip` button (bound per-SLOTS-row, src/lib/components/pawn/EquipmentDoll.svelte:18) never exists for it. The item is worn, contributes armour and fatigue, and is invisible and unremovable in the pawn panel.
  - No test asserts the list is complete: `grep -rln 'EquipmentDoll' src/tests/` returns nothing, and `grep -rn 'EquipmentDoll' src/` finds one consumer only, src/lib/components/pawn/PawnEquipment.svelte:4 and :24.
